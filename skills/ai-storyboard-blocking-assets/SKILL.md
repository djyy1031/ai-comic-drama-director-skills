# 分镜组站位资产

为 Patrick 的现有漫剧流程补上可视化空间依据。成品是实际场景中放入对应人物、朝向和必要道具的单幅图片，风格以用户认可的参考为准；文字、坐标、圆点示意图和生图提示词不能代替成品。

## 调用时机与边界

- 准备分镜组提示词时先读已锁定剧本和用户指定的本地资产目录，通过 `$ai-storyboard-asset-grounding` 核验实际资产。先完成本集资产匹配，再配合导演候选分镜确定每组的站位。
- 顺序为：剧本事实冻结 → 真实资产核验与本集匹配 → 表演和候选分镜 → 连续性检查 → 站位图生成或复用及图文核对 → 最终提示词编译。站位图发现问题时返回受影响的导演或连续性环节，修正后再编译。
- 主漫剧技能仍决定事件、台词、分镜组边界、时长和最终提示词。本技能不增加镜头、不改剧情、不为省图删除走位。
- 每个分镜组只关联一张站位图；多个相邻组可以关联同一文件。默认不增加每镜图、首尾帧对或额外干净版。用户明确只要文字时暂停图片生产。

## 读取与匹配本地资产

1. 沿用本项目已确认的目录；未提供时先在当前项目查找剧本、资产索引和已有目录。找不到再询问准确位置，不扫描无关私人目录。
2. 按每集剧情识别实际需要的场景、角色及服装状态、必要道具；跨集同名资产复用，不按集重复创建。当前只制作一集时不强制处理全剧。
3. 文件名仅用于检索，候选图片必须实际查看；已有核验记录仅在来源文件未变化且版本一致时复用。记录资产绝对路径和版本证据。
4. 单张场景图只证明可见结构。识别可站区域、固定家具、遮挡和光源，不臆造图外空间。人物图核对身份、服装、可用朝向；道具核对持有者和状态。
5. 多候选冲突、关键资产缺失或不可读时标记具体缺口，继续独立可做的组；受影响组不能标记图片已完成。不得凭名字猜图或自行生成替代资产。

## 一组一图的选择

- 图表示本组起始有效事件的空间关系；选择能看清必要人物关系的已核验场景视角，不必等同首镜的特写构图，也不强迫后续镜头保持该机位。
- 记录人物相对固定地标的位置、前中后景、身体朝向、视线对象、距离、姿态、道具持有者与左右手，以及允许的摄影机轴线侧。
- 组内走位继续写进逐镜提示词，并记录结束状态。一张图不表示整组所有时刻，不能为了让图始终成立把人物固定不动。
- 若已有上一组视频或可用结束画面，先核验实际结果。符合剧情与资产时以实际状态承接；明显错误不能继续继承，应报告需返修。无实际视频时用计划结束状态，明确这是计划承接而非实测。

## 复用判断

逐组比较上一张已审核图片、上一组结束状态与当前组起始状态，不只比较相邻两段文字；连续微移累积到旧图已误导时也要新图。

- 可以复用：同场景与资产状态；人物构成、身份服装、主要前后左右关系、身体朝向、视线关系、道具归属和主要光线仍适用。小步挪动、轻微重心变化或局部手势不改变这些关系，原图仍能准确指导本组。
- 换景别或正常切镜本身不强制新图；世界位置不随画面左右改变。若新视角需要图中未证明的空间，原图不能伪装成该视角依据。
- 需要新图：换场、人物进出、明显转身或坐站变化、交换位置、遮挡层次变化、递交道具或关键持物手变化、服装/光线等必要状态改变，或小幅移动已造成关系误读。不得只按固定像素百分比判断。
- 复用时引用同一个真实文件，不复制或重生图片；在该组外部说明复用哪张及简短原因。内部状态记录本组的细小变化，提示词仍完整复写本组站位。

## 从分镜组提取站位生图提示词

- 站位生图提示词必须来源于已经结合真实资产设计并经过连续性检查的分镜组方案。先明确该组所需场景、出镜人物、起始位置、朝向、视线和持物状态，再转换为生图指令；不得让生图环节另行安排人物，或要求 Patrick 逐组填写这些信息。
- 在图片生成之前，整理本组实际上传附件的顺序，建立“图片序号 → 资产标准名称 → 本地文件 → 用途”对应关系。提示词中的图一、图二必须与本次真实上传顺序一致；角色四视图中的多个人像是同一角色的角度参考，不是多个出场人物。附件调整后同步更新指令。
- 明确区分角色身份参考、场景空间依据、指定圈位和成品效果参考。效果参考只约束呈现形式，不能覆盖分镜、指定圈位或场景结构；示例角色、颜色和人数不固定套用到其他组。
- 场景有用户指定圈位时，逐人绑定圈位、姓名、朝向和视线，遵守实际落点，不能为构图好看移动圈位。没有圈位时，以已核验的地标和前中后景说明位置，不凭空写“蓝圈”“红圈”，也不要求用户先画圈。
- 把“互相对视”等模糊说法展开为可执行关系：明确各人看向谁；多人面对一人时，不要求该人同时与所有人双目对视，按分镜当前时刻确定主要视线对象。
- 检查角色—附件—落点—姓名标签是否一一对应。文字里重复颜色等明显笔误，只有上下文已唯一确定时才纠正并简短注明；存在实质歧义时只询问冲突项。
- 生图指令应包含：本组任务、附件对应、场景保留要求、每个人的位置与朝向及视线、必要姿态和道具状态、姓名标签、单幅输出要求。用可直接提交的自然中文描述，不仅给内部坐标或数据表。
- 新建图片时，将配套生图提示词与附件顺序说明保存到该组站位资产旁，供查看、复现和返修；与视频提示词分开。复用组引用已有图及原生图说明，不再发起生成。用户本次只要求站位提示词时交付该文本和附件对应即可，标记图片未生成。

## 图片生产与归档

- 沿用 Patrick 已表达的路线偏好：由 Codex 分析，使用 ChatGPT 网页图片生成并下载。执行前读取适用的 `chrome:control-chrome` 或 `browser:control-in-app-browser` 技能，确认现有工具、会话、上传和下载能力；按工具允许方式操作，不假定一定可用或一定省额度。
- 使用本轮明确允许上传的项目资产；历史设想不代表对未指定私人文件的上传授权。缺少登录或必要授权时只问缺口，先完成本地匹配和待生成内容。
- 不自动改为直接图片工具生成。网页不可用时报告状态并保留待生成包；用户明确选择直接生图后，读取对应图像技能并使用实际可用工具。
- 提交精确对应的场景、角色、道具参考与本站位要求，明确每张附件身份；保持场景可见结构、人物身份、服装、比例、透视、落脚、遮挡、朝向与持物关系。只生成单幅完整站位画面，不用四格或拼图。
- 默认按参考效果加准确的中文姓名标签。提示词说明标签和圈位仅用于识别，不属于场景，不得出现在视频中；用户选定无标签版本时改为无标签，默认不生成第二套。
- 首次生成后实际查看图片，核对所有必要人物、位置朝向、视线、道具、背景结构和标签，不能仅凭生成提示词或下载成功判定通过。局部错误优先针对修正，每张图默认最多两次返修；仍失败时保留结果与问题、停止该图重试，不无限消耗额度。
- 下载到本集站位图目录，文件名如 `第24集_分镜组一_站位图_v01.png`，沿用现有项目目录约定；不覆盖已有版本，核验本地文件确实可打开。保存真实格式，不把其他格式仅改扩展名冒充 PNG。
- 只有图文一致且真实文件已保存才标记完成；网页预览、待下载、失败稿及只有提示词均不能标记已完成。

## 输出和下游约定

- 交付分镜提示词文档及本次新增站位图；每组代码块外附本站位图链接/预览，或注明复用的图片。无需向 Patrick 展开内部资产清单和状态表。
- 内部保存简短站位索引：集与分镜组、源资产路径与版本、图片路径/版本、对应时刻、各人物状态、本组结束状态、计划或实测来源、新建或复用理由、审核状态和待解决问题。中断后从此恢复，不把未生成项伪装成复用。
- 最终提示词绑定本站位图标准名称，说明其用于人物身份及空间关系参考而非锁死所有镜头；起始站位、逐镜动作和实际图片必须一致，禁止把文件路径、审核记录混进纯净提示词。
- `$ai-shot-execution-continuity` 接收图像核验结果、站位索引和前组结束状态，复核跨组连续关系。有缺口时交付可审阅草稿并明确未完成，不能标记可生产。

## 跨风格通用能力

本技能对Seedance 2.0/2.5、仿真人、2D、3D、皮克斯式等风格、古装/现代及任意画幅使用同一套职责和检查逻辑。模型差异仅传入15秒或30秒单组上限。风格、时代、画幅与角色结构决定具体呈现、空间取景和材质，不作为启用或跳过专业能力的条件，不将某个预设当作全部支持范围。
