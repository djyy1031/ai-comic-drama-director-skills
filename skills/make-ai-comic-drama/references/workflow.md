# 工作流与状态

## 目的

把小说或剧本推进为可追溯的生产项目。每个阶段读取上游冻结结果，只在自己的职责内写入；发现上游问题时报告并返修，不暗中改剧情。

## 仅分镜组提示词的短流程

用户明确只要分镜组提示词时，使用 `STORYBOARD_PROMPTS_ONLY`，不建立长期项目目录，不进入 STAGE 03 至 STAGE 09。只执行本次需要的 STAGE 00配置确认、STAGE 01原文冻结、STAGE 01.5四层导演协作和 STAGE 02分镜组编译，然后按 [仅分镜组提示词交付](prompt-only-storyboard-delivery.md) 生成一份 Markdown 文档并运行专用校验脚本。资产绑定槽仍写进每组提示词，但不另行输出资产表。

## STAGE 00｜项目配置

以下配置必须全部由用户明确选择或确认后才能建立项目，禁止根据“漫剧”“短剧”等泛称自动推断：

- 项目名、输入来源与版权状态。
- `model_profile`：`seedance-2.0` 或 `seedance-2.5`。
- 2D、3D或其他明确视觉形态。
- 画幅、统一美术风格、主类型和导演知识包。
- 全局控制提示词内容与版本。仿真人古装、3D和其他视觉形态分别锁定，不得混用。
- 每集时长由原剧本可表现内容自然决定，不设置90秒、120秒或其他必须达到的下限；最终成片上限固定不超过180秒。
- 是否后期统一加字幕；默认禁止视频模型生成台词字幕。

缺失 `model_profile`、视觉形态、画幅、统一美术风格或全局控制提示词版本中的任一项时，将项目保持在 `WAITING_FOR_VISUAL_CONFIG`，集中询问缺失项。用户已经明确的配置不得重复询问。已有项目的任一项配置发生变化时，按配置迁移处理并使下游结果失效。

模型是项目级硬配置。切换模型等于迁移项目规则，必须新建版本并重新审核全部分镜组时长和复杂度。

## STAGE 01｜原文标准化与拆集

1. 保留章节、段落和原文顺序。
2. 原文已有集数时禁止重拆；只修复格式并建立映射。
3. 原文未拆集时，按完整冲突、人物选择、信息揭示、结尾钩子和场景切换自然划分；禁止为了达到某个时长添加或拉长内容。
4. 输出导演可读正文、机器可读集数映射及每集预计时长。
5. 任何压缩、合并或视听转译记录在改编说明中；不得改变核心事实、人物动机、事件顺序和剧情结果。

闸门：`EPISODES_READY`。

## STAGE 01.5｜导演意图与专业知识调用

1. 按完整事件建立导演调用请求，锁定不可修改剧情事实、原文台词、人物、场景、道具、上一组结束状态和本组预期结束状态。
2. 对白、独白、关系、威胁、喜剧、沉默或强情绪事件先调用 `$ai-character-performance-assets`，冻结人物目标、阻碍、策略变化、听者反应、身体任务、表演节拍和状态继承。
3. 使用 `$ai-cinematic-directing-assets` 吸收人物表演方案并完成场景诊断与候选镜头：主场景类型、剧情功能、战斗阶段、权力关系、信息目标、镜头功能、摄影语言、动作特效因果，以及动作触发的逐镜语言片段。
4. 候选镜头形成后调用 `$ai-shot-execution-continuity`，逐镜和逐切点检查第一帧、空间、朝向、视线、道具手、轴线、光线、物理、语言触发与连续承接；存在错误时返回最早问题位置返修候选镜头。
5. 三层结果通过后生成中性“导演镜头表示”，并记录每个模块的真实来源和状态。任一专业库不可用时只对该层使用内置规则降级并记录 `FALLBACK_INTERNAL`。
6. 审核导演表示未新增、删除、改写或调换剧情与台词，且镜头执行检查为 `PASS` 后，才进入模型提示词设计。

闸门依次为：`PERFORMANCE_PLAN_READY` → `SHOT_EXECUTION_CHECK_PASS` → `DIRECTOR_INTENT_READY`。

## STAGE 02｜分镜组、镜头与冻结

1. 读取已通过的导演镜头表示，根据当前模型参考文件划分分镜组。
2. 每组围绕一个完整事件、连续对话、连续动作或稳定空间关系。
3. 每组包含多个小镜头；每个小镜头只承担一个主要叙事或动作任务。
4. 为每组记录场景、初始站位、角色、道具、事件、逐镜时间、镜头功能、存在理由和结束状态。
5. 同场景长内容在完整语义、完整情绪落点或完整动作结束处拆组，禁止切在一句台词、连续动作或人物走位中间。
6. 同场景相邻组分别复写一致的空间锚点、光影、天气、风向、人物左右关系和摄影轴线；使用视线匹配、正反打、动作完成点或连续声音衔接，不把重复首尾帧作为默认方案。
7. 普通完整台词不改写、不重复；长语言先冻结完整语言单元，再在同一分镜组拆成多个独立计时镜头。第一片段由动作或现场事件触发，后续片段无停顿承接，并保持音色、音量、呼吸、口型和情绪连续。
8. 普通对话镜头以2～5秒为主，默认不得超过6秒。分镜组超过6秒时必须包含多个镜头；只有用户或原文明示一镜到底并记录批准和理由时才可例外。
9. 把中性导演表示编译为所选模型的提示词；专业库不能替代Seedance模型适配、资产绑定和纯净提示词格式。
10. 汇总分镜组及片头、标题、转场停顿、结尾画面。核对每一秒是否承载剧情、表演、环境反馈或有效镜头语言；最终成片不得超过180秒。
11. 完成原文忠实度与导演越权审核后生成 `SHOTGROUP_LOCK_V1`。

冻结后：

- 资产模块不能修改剧情、台词顺序或镜头事件。
- 发现问题时输出 `FLAG`、影响范围和返修建议。
- 需要修改时建立新版本，重新运行受影响审核，不能覆盖旧版本的追溯记录。

闸门：`SHOTGROUPS_LOCKED`。

## STAGE 03｜母资产扫描与去重

扫描当前已确认范围内的全部剧本，识别角色、服装、状态、场景、道具、武器、生物、载具、UI、VFX、环境和声音资产。

- 先查已有母资产，再决定复用、建立变体或新建。
- 场景结构永久改变时创建状态变体；摄影机变化只创建机位资产。
- 内部可使用稳定ID去重，面向人和视频模型始终使用原文标准名称。

闸门：`MASTER_ASSET_ANALYSIS_READY`。

## STAGE 04｜母资产提示词

按项目风格生成真正需要的资产提示词：

- 角色基础设定及必要视图、服装和状态变体。
- 场景空间母图及按实际需求选择的机位图。
- 道具或武器三视图、必要的比例与持握参考。
- UI、VFX和高频声音母资产。

提示词生成后先审核一致性、复用价值和数量，再交给用户生产图片或声音。

闸门：`MASTER_PROMPTS_READY`。允许暂停为 `WAITING_FOR_MASTER_ASSETS`。

## STAGE 05｜子资产与站位

逐集逐分镜组判断 Blocking、Seating、Pose、Character+Prop、Expression、Interaction，以及极少数特殊镜头才需要的 Start Frame 和 End Frame。

- 每组都有文字起始站位，不代表每组都生成站位图。
- 以0不需要、1可选、2建议、3必须评分。
- 多人复杂调度、交叉动作、重要持物、打斗和精确连续性优先生成。
- 简单单人或稳定双人场景避免过度生产。
- Start Frame 和 End Frame 默认评分为0，禁止为了普通同场景衔接常规生产；只有用户明确要求或普通场景、站位、轴线与剪辑约束仍无法解决时才评估。

闸门：`SUB_ASSET_ANALYSIS_READY`。

## STAGE 06｜生产表、视频包与声音蓝图

生成六类结构化结果：母资产总表、场景机位矩阵、分镜组资产矩阵、子资产生产清单、视频输入包、分集声音执行表的蓝图版。

视频输入包同时保留：

- 分镜组资产矩阵：结构化记录每组资产依赖和锁定职责。
- 制作说明与衔接：告诉用户如何执行、缺什么，以及如何继承场景、光影、轴线、站位、视线、道具和声音；默认不依赖上一组末帧。
- 纯净视频提示词：按项目对应的全局固定段、等号资产绑定区、摄影机总设定、场景与光影、起始站位、逐镜时间段的顺序输出。只做分镜提示词、不跑资产清单时，等号资产绑定区仍不得省略。

闸门：`PRODUCTION_TABLES_READY`。

## STAGE 07｜三轮审核与生产裁决

按 [审核与状态闸门](audits-and-state.md) 分别运行三轮审核。全部通过后才设置：

`PRODUCTION_READY = TRUE`

## STAGE 08｜资产与视频生产

用户生产资产后先接入资产文件夹：

1. 保存资产文件夹绝对路径，但不自动移动、复制、删除或重命名源文件。
2. 扫描文件名、扩展名和目录结构，按原文标准名称与资产表自动匹配。
3. 输出已匹配、缺失、多候选和未识别文件，不要求用户手工回填资产表。
4. 对每个候选文件进行真实内容审核；文件名正确但画面错误时不得标记完成。
5. 详细规则见 [资产文件夹接入与逐项审核](asset-folder-review.md)。

审核完成后更新状态：

- 已完成资产标记 `READY`。
- 必须资产缺失时，对应视频任务保持 `NOT_READY_FOR_VIDEO`。
- 不重复生成已完成资产，不伪装不存在的文件或状态。

视频任务使用已冻结分镜与已完成资产生成。失败重试不得擅自改剧情；需要简化时先报告复杂度问题并建立返修版本。

## STAGE 09｜粗剪、声音与最终成片

1. 视频完成后形成粗剪，记录真实时间码。
2. 将声音蓝图校准为最终 BGM、环境声、动作声、转场声、剧情专用音效和静默执行表。
3. 审核对白避让、声音连续、资产授权和最终成片时长。
4. 最终成片不超过180秒且声音审核通过，才设置：

`FINAL_EPISODE_READY = TRUE`

## 暂停与继续

- 每个闸门写入 `PROJECT_STATUS.json`。
- `continue` 从最后一个已通过闸门之后开始，先扫描上游文件、导演表示、状态账本和项目状态是否仍一致。
- 配置、冻结分镜或母资产发生版本变化时，使所有依赖结果过期并重新审核。
- 不用“已经完成”描述未验证的外部图片、音频或视频。
